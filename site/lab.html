The technology, without the match.

Two pieces of MatchReplay to play with directly: the live win probability model, and the logic that keeps live numbers right when the data arrives late, out of order or twice. Everything below runs the same code the site uses, on real data.

2

Correct numbers from a messy feed

A live feed never arrives in order: some events come seconds late, some come twice. The pipeline waits a little before it trusts a 5-second window of play, drops duplicates, and puts late events back in their place. Wait too little and late events miss their window; wait longer and the numbers come later. Turn the knobs and run a real match through it.

In the real pipeline this logic is a Java operator in Apache Flink, with its state checkpointed so a crashed server resumes without losing or double-counting a goal. GitHub runs it on every change against the same principle shown here: the output of the messy feed must equal the output of the perfect one.
